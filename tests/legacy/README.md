# Legacy baseline harness

This directory preserves reference outputs and benchmarks for the
pre-redesign SAYRAM2D implementation. It is intentionally tied to the legacy
`Equation`/`Mesh`/`Solver` API and is not part of the new library.

## Status of the existing test suite

The repository contained **no automated tests, test directory, CTest setup,
or test target** before this baseline was created. The baseline harness below
is therefore the first reproducible numerical test suite for the legacy code.

| Linear algebra | `Eigen::SparseLU<SpMat, Eigen::COLAMDOrdering<int>>` |

The repository's original `Makefile` is not directly usable in this
environment: it points HDF5 at `/opt/local`, omits an explicit C++ standard,
and Apple clang 17 fails while instantiating `xt::xarray` with the installed
xtensor/xtl combination. GCC 16 with the Homebrew HDF5 headers builds the
legacy source unchanged. This is a build-environment finding, not a numerical
change.

## Build and reproduction

From the repository root:

```bash
make -C tests/legacy reference
make -C tests/legacy benchmark
cd tests/legacy && make run-reference
cd tests/legacy && make run-benchmark
```

`run-reference` writes `tests/legacy/reference/*.csv`; `run-benchmark` writes
`tests/legacy/results/benchmark_original.csv`. The benchmark target uses a
temporary copy of `source/Solver.cc` generated by
`tests/legacy/make_timed_solver.py`; only `std::chrono` timing calls are
inserted. The numerical code is otherwise copied verbatim.

## Reference cases

All cases use `dt = 0.01`, five steps, a smooth positive initial condition, and
a smooth positive boundary function. `G`, `D11`, `D22`, and (for off-diagonal
cases) `D12 = 0.20` vary in space in the "varying" cases. Boundary values are
the same function on every Dirichlet side, so corner values are consistent.
The all-ZeroFlux case is the conservation check.

| File | Mesh | D | Boundary | `1/tau` |
|---|---|---|---|---|
| `uniform_diag_all_dirichlet.csv` | uniform 12×10 | diagonal | all Dirichlet | 0 |
| `nonuniform_diag_mixed.csv` | nonuniform 10×11 | diagonal | Q1Min/Q2Min Dirichlet, Q1Max/Q2Max ZeroFlux | 0 |
| `nonuniform_offdiag_mixed.csv` | nonuniform 10×11 | off-diagonal | same mixed | 0 |
| `uniform_offdiag_all_zeroflux.csv` | uniform 12×10 | off-diagonal | all ZeroFlux | 0 |
| `nonuniform_offdiag_loss.csv` | nonuniform 10×11 | off-diagonal | mixed | +0.5 |
| `nonuniform_offdiag_source_legacy.csv` | nonuniform 10×11 | off-diagonal | mixed | -0.1 |

Each CSV contains the mesh edges, cell coefficients, all six time frames
(`f0`–`f5`), mass, and minimum values. The complete arrays are stored at
17-digit precision. The positive-loss case exercises the legacy implicit loss
diagonal.

| Case | Initial mass | Final mass | Minimum final `f` |
|---|---:|---:|---:|
| uniform_diag_all_dirichlet | 1.2015643986272673 | 0.78935588150928349 | 0.48774406151108246 |
| nonuniform_diag_mixed | 1.2015063396622134 | 0.96255543378083741 | 0.46289348311238876 |
| nonuniform_offdiag_mixed | 1.2015063396622134 | 0.96132035024051299 | 0.46006430109464708 |
| uniform_offdiag_all_zeroflux | 1.2015643986272673 | 1.2015643986272668 | 0.9702200879984183 |
| nonuniform_offdiag_loss | 1.2015063396622134 | 0.94250566689525028 | 0.4577794726090344 |
| nonuniform_offdiag_source_legacy | 1.2015063396622134 | 0.96514526088045072 | 0.46052734069211737 |

The all-ZeroFlux case conserves mass to `3.7e-16` relative error, and every
case remains positive. The Dirichlet and mixed cases lose mass through the
prescribed boundary values, as expected.

### Legacy discrepancy: negative inverse loss

The algorithm document specifies that `tau < 0` is an explicit source added to
the right-hand side. The legacy solver does not implement that branch: it only
uses `1 + dt*inv_tau` on the diagonal. The `nonuniform_offdiag_source_legacy`
reference therefore records the legacy behavior, **not** the documented source
discretization. The redesign is expected to implement the documented source
branch; this case should not be used as a numerical-agreement target for
negative `tau`.

A second known discrepancy is that the legacy solver has no representation for
nonzero Neumann flux (`q_N`); its only non-Dirichlet condition is `ZeroFlux`.
The redesign's initial scope is also Dirichlet/ZeroFlux only, so this remains a
documented limitation rather than a regression.

## Benchmark

Configuration for every row: uniform grid on `[0,1] × [0,1.2]`, `dt=0.01`,
three solves, mixed Dirichlet/ZeroFlux boundaries, diagonal `G=D=1`, zero
loss. The first solve includes the first numeric factorization; repeated
columns are averages of the remaining solves. Times are seconds, measured
with `std::chrono::steady_clock`; RSS is `getrusage(RUSAGE_SELF).ru_maxrss`
(macOS reports bytes; converted to MiB in the table).

| Grid | Steps | Construction | First total | First assemble | First factorize | First solve | Repeated total | Peak RSS |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 50×50 | 3 | 0.0031 | 0.0063 | 0.0006 | 0.0055 | 0.0002 | 0.0056 | 7.6 MiB |
| 100×100 | 3 | 0.0047 | 0.0187 | 0.0015 | 0.0167 | 0.0005 | 0.0161 | 22.4 MiB |
| 200×200 | 3 | 0.0135 | 0.0787 | 0.0060 | 0.0704 | 0.0022 | 0.0792 | 97.5 MiB |
| 500×500 | 3 | 0.0941 | 0.9063 | 0.0531 | 0.8310 | 0.0214 | 0.8810 | 672.2 MiB |

The linear factorization dominates the solve. Assembly is a small fraction at
these sizes. The 500×500 case uses a large `SparseLU` factor and has a high
peak RSS; this is the main performance/memory pressure the redesign should
retain or improve.
